## Motivation

The RBAC implementation currently uses `JdbcTemplate` directly in guards and service implementations. The SQL is parameterized and functionally valid, but the persistence details are coupled to authorization policy code. This makes unit testing harder, increases schema coupling, and leaves scope lookups distributed across security components.

## Baseline

- Direct SQL is present in the authorization guard, resource scope resolver, authorization service, admin service, mutation service, and audit service.
- The authorization service loads snapshots from Redis first and falls back to database reads.
- Existing backend tests and frontend production build pass before this improvement.
- The existing RBAC contracts and Flyway migrations must remain backward compatible.

## Out of Scope

- Redesigning role or permission semantics.
- Changing Flyway schema or production data.
- Replacing `JdbcTemplate` with JPA everywhere.
- Changing frontend authorization behavior or API response contracts.
- Adding an external policy engine.
- Committing changes to Git.
