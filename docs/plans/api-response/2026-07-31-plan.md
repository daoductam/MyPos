# 1. Context

**Problem:**
The Java Spring Boot backend currently uses disparate response structures (`ApiResponseBody`, `ApiResponse`, `ExceptionResponse`, raw DTOs, raw Lists), making API consumption unpredictable for the Frontend. Standardizing responses under a single generic `ApiResponse<T>` wrapper and centralized `ErrorCode` enum ensures clean contract consistency across all endpoints and exception handlers.

**Affected Modules:**
- `Backend/src/main/java/com/tamdao/payload/response` — API Response DTOs
- `Backend/src/main/java/com/tamdao/exception` — Error handling & Exception hierarchy
- `Backend/src/main/java/com/tamdao/configurations` — Spring Web auto-wrapping Interceptor

**Non-Goals:**
- Modifying frontend React components (handled in follow-up task).
- Breaking existing REST route endpoints.

---

# 2. Constraints

**Language:** Java 21 / Spring Boot 3.5+  
**Architecture:** RESTful Spring MVC  

**Rules:**
- Do NOT break existing HTTP status codes.
- Do NOT break OpenAPI / Swagger UI JSON generation.
- Safely handle Controller endpoints returning `String` without Jackson serialization `ClassCastException`.

---

# 3. Conventions

**Naming:**
- Classes: `PascalCase` — e.g. `ApiResponse`, `GlobalResponseBodyAdvice`
- Package: `com.tamdao.payload.response` and `com.tamdao.exception`

**Error Handling:**
- Throw `BusinessException` with specific `ErrorCode`.
- Catch and format all exceptions in `GlobalExceptionHandler`.

---

# 4. Contracts

## Data Structure: `ApiResponse<T>`
```java
ApiResponse<T> {
  success:    boolean
  code:       String
  message:    String
  data:       T (nullable)
  errors:     List<FieldErrorDetail> (nullable)
  timestamp:  String (ISO-8601 UTC)
}
```

## Data Structure: `FieldErrorDetail`
```java
FieldErrorDetail {
  field:   String
  message: String
}
```

## Enum: `ErrorCode`
- `SUCCESS` (200 OK)
- `INVALID_REQUEST` (400 Bad Request)
- `UNAUTHENTICATED` (401 Unauthorized)
- `UNAUTHORIZED` (403 Forbidden)
- `RESOURCE_NOT_FOUND` (404 Not Found)
- `DATA_INTEGRITY_VIOLATION` (409 Conflict)
- `USER_NOT_FOUND` (404 Not Found)
- `USER_EXISTED` (400 Bad Request)
- `PRODUCT_NOT_FOUND` (404 Not Found)
- `OUT_OF_STOCK` (400 Bad Request)
- `UNCATEGORIZED_EXCEPTION` (500 Internal Server Error)

# 5. Target Architecture

```
Client Request
      │
      ▼
Spring RestController (returns DTO/List/String)
      │
      ├── [Normal Return] ──► GlobalResponseBodyAdvice.beforeBodyWrite() ──► Wrap into ApiResponse<T>.success()
      │
      └── [Exception Thrown] ──► GlobalExceptionHandler.handleX() ──► Return ResponseEntity<ApiResponse<Void>>
```

# 8. Task Specifications

## TASK-001: Create `FieldErrorDetail` and `ApiResponse<T>` DTOs
**Files:**
- `Backend/src/main/java/com/tamdao/payload/response/FieldErrorDetail.java` — **create**
- `Backend/src/main/java/com/tamdao/payload/response/ApiResponse.java` — **modify/create**

**Acceptance Criteria:**
- [ ] `ApiResponse.success(data)` returns `ApiResponse<T>` with `success=true`, `code="SUCCESS"`, `timestamp` non-null.
- [ ] `ApiResponse.error(code, message)` returns `ApiResponse<T>` with `success=false`.

## TASK-002: Create `ErrorCode` Enum & `BusinessException` Class
**Files:**
- `Backend/src/main/java/com/tamdao/exception/ErrorCode.java` — **create**
- `Backend/src/main/java/com/tamdao/exception/BusinessException.java` — **create**

**Acceptance Criteria:**
- [ ] `BusinessException` holds `ErrorCode` and custom message.

## TASK-003: Implement `GlobalResponseBodyAdvice` Interceptor
**Files:**
- `Backend/src/main/java/com/tamdao/configurations/GlobalResponseBodyAdvice.java` — **create**

**Acceptance Criteria:**
- [ ] Controller returning `UserDTO` automatically gets wrapped into `ApiResponse<UserDTO>`.
- [ ] Controller returning `String` correctly serializes to JSON string without `ClassCastException`.
- [ ] Swagger/OpenAPI documentation endpoints are ignored.

## TASK-004: Refactor `GlobalExceptionHandler`
**Files:**
- `Backend/src/main/java/com/tamdao/exception/GlobalExceptionHandler.java` — **modify**

**Acceptance Criteria:**
- [ ] `BusinessException` is caught and returned as `ResponseEntity<ApiResponse<Void>>` with corresponding HTTP status.
- [ ] Validation exceptions include `FieldErrorDetail` list.
- [ ] DB constraint violations return `DATA_CONFLICT` error code.

## TASK-005: Verification
**Acceptance Criteria:**
- [ ] `./mvnw test-compile` passes cleanly.

# 9. Edge Cases

| # | Scenario | Expected Behavior | Handled In |
|---|----------|-------------------|------------|
| 1 | Controller returns `String` | `GlobalResponseBodyAdvice` converts `ApiResponse` to JSON String using `ObjectMapper` and sets `Content-Type: application/json` | TASK-003 |
| 2 | Controller returns object already of type `ApiResponse` | Interceptor returns `body` directly without double-wrapping | TASK-003 |
| 3 | Endpoint belongs to Swagger/OpenAPI | Interceptor skips wrapping | TASK-003 |
| 4 | Method argument validation fails | `GlobalExceptionHandler` extracts field errors into `errors` list in `ApiResponse` | TASK-004 |
