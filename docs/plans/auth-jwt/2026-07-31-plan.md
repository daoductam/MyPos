# 1. Context

**Problem:**
Hệ thống POS hiện tại chỉ dùng Single Access Token với thời hạn 24 giờ. Nếu token bị lộ, không thể hủy hay khóa phiên truy cập của user. Thiếu Refresh Token làm tăng rủi ro bảo mật và không hỗ trợ cơ chế xoay vòng token hay đăng xuất an toàn.

**Affected Modules:**
- `Backend/pom.xml` — Thêm dependency `spring-boot-starter-data-redis`
- `Backend/src/main/resources/application.properties` — Cấu hình kết nối Redis
- `Backend/src/main/java/com/tamdao/configurations/` — Cấu hình `RedisConfig`, cập nhật `JwtProvider` và `JwtValidator`
- `Backend/src/main/java/com/tamdao/service/` — Tạo `RedisTokenService`, cập nhật `AuthService`
- `Backend/src/main/java/com/tamdao/controller/AuthController.java` — Thêm endpoints `/auth/refresh` và `/auth/logout`
- `Backend/src/main/java/com/tamdao/payload/` — Thêm DTO request/response liên quan

**Non-Goals:**
- Quản lý giao diện danh sách các thiết bị đang đăng nhập trên Frontend trong đợt này.

# 2. Constraints

**Language:** Java 21, Spring Boot 3.5+
**Architecture:** RESTful API Layered Architecture (Controller -> Service -> Redis / Repository)

**Rules:**
- Giữ tương thích ngược tối đa với API đăng nhập/đăng ký hiện tại.
- Tuân thủ quy tắc bảo mật Multi-Tenant và Stateless Access Token.

**Performance Budgets:**
- Latency Redis lookup trong `JwtValidator`: < 2ms.
- Phản hồi API `/auth/refresh`: < 50ms.

---

# 3. Conventions

**Naming:**
- Classes: `PascalCase` — e.g. `RedisTokenService`, `JwtValidator`
- Methods: `camelCase` — e.g. `saveRefreshToken()`, `isBlacklisted()`
- Redis Keys: `rt:{userId}:{tokenId}` cho Refresh Token, `bl:{accessToken}` cho Blacklist Access Token.

**Error Handling:**
- Throw `BusinessException` với `ErrorCode.UNAUTHENTICATED` ("Token không hợp lệ hoặc đã bị thu hồi").

# 4. Contracts

## Interface: `RedisTokenService`

```
saveRefreshToken(userId: Long, tokenId: String, refreshToken: String, durationMs: long): void
  - pre: userId, tokenId, refreshToken non-null
  - post: lưu key `rt:{userId}:{tokenId}` vào Redis với TTL durationMs

isValidRefreshToken(userId: Long, tokenId: String, refreshToken: String): boolean
  - pre: non-null parameters
  - post: trả về true nếu key tồn tại và trùng giá trị refreshToken

deleteRefreshToken(userId: Long, tokenId: String): void
  - pre: non-null parameters
  - post: xóa key `rt:{userId}:{tokenId}` khỏi Redis

revokeAllUserTokens(userId: Long): void
  - pre: userId non-null
  - post: tìm và xóa toàn bộ key `rt:{userId}:*` khỏi Redis (dùng khi phát hiện gian lận token)

blacklistAccessToken(accessToken: String, remainingTtlMs: long): void
  - pre: accessToken non-null, remainingTtlMs > 0
  - post: lưu key `bl:{accessToken}` vào Redis với TTL remainingTtlMs

isBlacklisted(accessToken: String): boolean
  - pre: accessToken non-null
  - post: trả về true nếu key `bl:{accessToken}` tồn tại trong Redis
```

# 5. Target Architecture

**Components:**
- `RedisConfig` — Cấu hình `RedisTemplate<String, String>`
- `RedisTokenService` — Service giao tiếp Redis lưu trữ Refresh Token & Blacklist
- `JwtProvider` — Phát hành Access Token (15m) & Refresh Token (7d)
- `JwtValidator` — Filter kiểm tra chữ ký JWT + Check Redis Blacklist
- `AuthServiceImpl` — Xử lý logic Signup, Login, Refresh (Rotation & Theft Detection), Logout

**Interaction Flow:**

```
Client (Frontend)
  │
  ├──> POST /auth/login ──> AuthController ──> AuthServiceImpl
  │                                                ├──> JwtProvider.generateAccessToken()
  │                                                ├──> JwtProvider.generateRefreshToken()
  │                                                └──> RedisTokenService.saveRefreshToken()
  │                                           <── Trả về { accessToken, refreshToken }
  │
  ├──> GET /api/* ──> JwtValidator ──> RedisTokenService.isBlacklisted(accessToken)?
  │                         ├── [Có trong Blacklist] ──> Reject 401 Unauthorized
  │                         └── [Hợp lệ] ──> Cho phép vào Controller
  │
  ├──> POST /auth/refresh ──> AuthServiceImpl
  │                                ├── RedisTokenService.isValidRefreshToken()?
  │                                ├── [Nếu KHÔNG có] ──> RedisTokenService.revokeAllUserTokens() (Phát hiện trộm token)
  │                                └── [Nếu HỢP LỆ] ──> Delete RT cũ, tạo AT mới + RT mới, Save RT mới
  │
  └──> POST /auth/logout ──> AuthServiceImpl
                                   ├── RedisTokenService.blacklistAccessToken(accessToken)
                                   └── RedisTokenService.deleteRefreshToken(refreshToken)
```

# 9. Edge Cases

| # | Scenario | Expected Behavior | Handled In |
|---|----------|-------------------|------------|
| 1 | Refresh Token đã bị xoay vòng từ trước (Reuse attack) | Revoke toàn bộ Refresh Token của User trong Redis và trả lỗi 401 | TASK-006 |
| 2 | Access Token đã hết hạn khi gửi request Logout | Vẫn tiến hành xóa Refresh Token trong Redis, không cần add vào Blacklist vì token đã hết hạn | TASK-006 |
| 3 | Redis service tạm thời gián đoạn | Catch exception, fallback log warning hoặc throw Internal Error phù hợp | TASK-002 |
