# Spec: Dual-Token JWT Authentication với Refresh Token Rotation và Redis Blacklist

## 1. Tổng quan & Mục tiêu (Overview & Goals)
Nâng cấp cơ chế xác thực từ **Single Access Token (24h)** hiện tại sang mô hình **Dual-Token (Access Token + Refresh Token)** sử dụng **Spring Data Redis** để quản lý trạng thái phiên đăng nhập, thu hồi token (blacklist) và bảo vệ an toàn tối đa bằng cơ chế **Refresh Token Rotation (Xoay vòng token)** & **Reuse Detection (Phát hiện trộm token)**.

---

## 2. Thông số Thời gian sống (Expiration Policy)
* **Access Token**:
  * Thời hạn: **15 phút** (900,000 ms).
  * Mục đích: Stateless token ngắn hạn mang thông tin mã hóa (email, roles, storeId).
* **Refresh Token**:
  * Thời hạn: **7 ngày** (604,800,000 ms).
  * Mục đích: Stateful token lưu tại Redis dùng để xin cấp lại cặp Access Token & Refresh Token mới khi Access Token cũ hết hạn.

---

## 3. Cấu trúc dữ liệu Redis (Redis Key Design)

### 3.1. Refresh Token Store
* **Key Format**: `rt:{userId}:{tokenId}`
* **Value**: String (ví dụ: `active`)
* **TTL**: 7 ngày (604800s)

### 3.2. Access Token Blacklist
* **Key Format**: `bl:{accessToken}`
* **Value**: String (ví dụ: `logout` hoặc `revoked`)
* **TTL**: Thời gian còn lại của Access Token tính từ thời điểm Logout (Max 15 phút).

---

## 4. Danh sách API Endpoints & Payload Contracts

### 4.1. `POST /auth/signup` & `POST /auth/login`
* **Response Payload (`AuthResponse`)**:
  ```json
  {
    "title": "Login success",
    "message": "Welcome back user@example.com",
    "accessToken": "eyJhbGciOi...",
    "refreshToken": "df98a123-...",
    "user": { ... }
  }
  ```

### 4.2. `POST /auth/refresh`
* **Request Payload (`RefreshTokenRequest`)**:
  ```json
  {
    "refreshToken": "df98a123-..."
  }
  ```
* **Response Payload (`TokenRefreshResponse`)**:
  ```json
  {
    "accessToken": "eyJhbGciOi...",
    "refreshToken": "e019b456-...",
    "tokenType": "Bearer"
  }
  ```

### 4.3. `POST /auth/logout`
* **Headers**: `Authorization: Bearer <accessToken>`
* **Request Payload (`LogoutRequest`)**:
  ```json
  {
    "refreshToken": "e019b456-..."
  }
  ```
* **Response Payload (`ApiResponse`)**:
  ```json
  {
    "status": 200,
    "message": "Logout successful",
    "data": null
  }
  ```

## 5. Các Luồng Nghiệp vụ Chi tiết (Detailed Flows)

### 5.1. Luồng Đăng nhập / Đăng ký
1. Xác thực thông tin người dùng (Email/Password).
2. Tạo **Access Token** (hạn 15 phút).
3. Tạo UUID ngẫu nhiên làm **Refresh Token** (hạn 7 ngày).
4. Lưu Refresh Token vào Redis với key `rt:{userId}:{tokenId}`.
5. Trả về cả 2 token cho Client.

### 5.2. Luồng Refresh Token (Rotation & Reuse Detection)
1. Client gửi `refreshToken` cũ đến API `POST /auth/refresh`.
2. Backend kiểm tra `refreshToken` trong Redis:
   - **TH1: Hợp lệ (Tồn tại trong Redis)**:
     * Xóa ngay `refreshToken` cũ khỏi Redis.
     * Tạo **Access Token mới** + **Refresh Token mới**.
     * Lưu Refresh Token mới vào Redis `rt:{userId}:{newTokenId}`.
     * Trả cặp token mới về cho Client.
   - **TH2: Gian lận / Dùng lại token (Reuse Attack)**:
     * `refreshToken` không tìm thấy trong Redis (do đã bị xoay vòng hoặc thu hồi trước đó).
     * Backend phát hiện rò rỉ token $\rightarrow$ **Xóa toàn bộ các key `rt:{userId}:*` của user đó trong Redis** $\rightarrow$ Ép đăng xuất trên tất cả các thiết bị.
     * Ném ngoại lệ `UNAUTHENTICATED` ("Refresh token invalid or stolen").

### 5.3. Luồng Đăng xuất (Logout)
1. Lấy Access Token từ Header `Authorization`.
2. Tính thời hạn còn lại của Access Token = `expirationDate - currentTime`.
3. Lưu Access Token vào Redis `bl:{accessToken}` với TTL bằng thời hạn còn lại.
4. Lấy `refreshToken` từ body request, xóa khỏi Redis `rt:{userId}:{tokenId}`.

### 5.4. Luồng Kiểm tra Request (`JwtValidator`)
1. Trích xuất Access Token từ Header `Authorization`.
2. Kiểm tra chữ ký & hạn sử dụng JWT.
3. Kiểm tra xem Access Token có nằm trong Redis Blacklist (`bl:{accessToken}`) không.
   - Nếu có trong Blacklist $\rightarrow$ Từ chối request (`BadCredentialsException` / `401 Unauthorized`).
   - Nếu không có $\rightarrow$ Đặt Authentication vào `SecurityContextHolder`.

---

## 6. Kế hoạch Kiểm thử & Xử lý lỗi (Verification & Security)
- **Unit & Integration Test**:
  - Test sinh token và Verify token hợp lệ.
  - Test Refresh Token thành công (thu hồi token cũ, cấp token mới).
  - Test Refresh Token reuse attack (xoá toàn bộ token gia đình).
  - Test Access Token sau khi Logout bị từ chối bởi `JwtValidator`.
- **Performance**:
  - Đảm bảo Redis check trong `JwtValidator` phản hồi $< 2ms$.
